# Mode NEW — draft a new Decision Record

_On-demand procedure for decision-records' NEW mode. The prefix table, naming convention, and placement rule live in [`SKILL.md`](../SKILL.md) and are already loaded; the full format with required sections and writing guidance is in [the Decision Records standard](standards-decision-records.md)._

1. Inspect the decisions directory and index. If no Decision Records exist, establish the collection first: add `<!-- ki-decision-records: adoption-root -->` to the index, then write **`GDR-<SCOPE>-001: Adopting Decision Records`** and place its index entry first. Do not ask the user to choose a different first type or title; author their requested distinct decision only after this root exists. The marker gives AUDIT a durable new-collection boundary without rewriting established collections.
2. Otherwise, first search the current collection for the record that owns the concern. If the proposed decision refines, qualifies, or changes that record, edit it in place and stop: do not create a parallel record. Only for a genuinely independent decision, determine the `decision_type` (one of the nine values) and derive the prefix from the table in `SKILL.md`. Determine the `SCOPE` from `.ki-config.toml` (e.g. `ARCADIA`). Derive the next available `NNN` from existing files — serials are **per prefix within the scope**, so scan the `<PREFIX>-<SCOPE>-NNN` files that share this prefix (a `GDR-` and an `SDR-` in the same scope may both be `001`).
3. Write the DR using [the template](standards-decision-records.md#templates) — required frontmatter (`id`, `title`, `date`, `status`, `decision_type`, and `decision_type_url`), the Nygard body sections (Title, Context, Decision, Consequences), and an optional `## References` section. There is no bold Status, Mutability, Changelog, or historical/supersession framing — a DR that exists is in effect.
4. Add an entry to the index list in reveal order.
5. If this decision revises the direction of an existing DR, **edit that record in place** so it reflects the new decision; author a new record only for a genuinely distinct decision.
6. Run **AUDIT** to confirm the new file is well-formed.
