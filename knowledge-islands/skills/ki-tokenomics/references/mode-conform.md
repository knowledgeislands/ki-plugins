# Mode CONFORM — route deliberate token-cost changes

_On-demand procedure for `ki-tokenomics` CONFORM. It begins with [AUDIT](mode-audit.md)._

The native session is report-only: changing standing instructions, memories, MCP availability, model selection, proxy routing, or Headroom state can remove capabilities or destroy operational history, so it publishes no automatic writes or commands.

1. Run [AUDIT](mode-audit.md) for the attributed gap list.
2. Route each change to its owner: `ki-skills` for skill descriptions, `ki-mcp` for server design, `ki-kb` for base structure, and the repository's own governance for local settings.
3. Review exact targets and diffs before trimming instructions, pruning memory, disabling or scoping MCP servers, changing model/runtime settings, or introducing compression tooling.
4. For Headroom ledgers, logs, counters, and durable savings, follow [the Headroom operational safety standard](standards-headroom-operations.md). Snapshot and confirm the exact store; all reset, truncate, move, and delete operations remain manual.
5. Re-run [AUDIT](mode-audit.md) after deliberate changes.
