# Sources — where the model comes from

**Refresh:** canonical · on-change

This skill is the canonical definition of the `Streams/` operational container. Knowledge Bases defer to it through thin local process notes that add only local bindings; no base's historic Focus structure is a source of the target model.

REFRESH checks that the target remains usable against current receiver practice. It may promote a shared pattern into this skill, but leaves a receiving base's record classification, identifier allocation, and path migration to that base. It records the review date here; Git history records the changes.

## Canonical

- [the SKILL body](../SKILL.md) — container boundary, operational areas, and adapter routing.
- [the Streams structure standard](standards-streams-structure.md) — `Streams/Roadmap/`, `Streams/Housekeeping/`, legacy migration, and retention.
- [the Enactment Process standard](standards-enactment-process.md) — the always-loaded canonical-change gate.
- [the rubric](rubric.md) and its native `scripts/rubric/items/index.ts` catalogue — checkable container criteria.

## Living practice

Receiver Knowledge Bases are evidence of migration needs, not sources of the target layout. A refresh may inspect their local `Streams/` zones and always-loaded instructions only to identify a receiver-owned classification or migration decision.
